# kit/agui Runtime + Thread contract
Type: decision
Status: implemented (kit 416776a)
Date: 2026-11-25

## Decision

1. Add a contract-only `Runtime` / `Thread` surface to `kit/agui` — no backend, no storage, no runner. Apps compile against `kit` alone; `apliq` provides the implementation later.
2. Freeze this exact surface in `agui/runtime.go` (contract only, zero backend):

```go
package agui

type Runtime struct{ /* unexported */ }
type Thread struct{ /* unexported */ }

func NewRuntime() *Runtime

func (r *Runtime) CreateThread(ctx context.Context) (Thread, error)
func (r *Runtime) OpenThread(threadID string) (Thread, error)
func (r *Runtime) Resume(ctx context.Context) ([]Thread, error)
func (r *Runtime) ListActiveRuns(ctx context.Context, owner string) ([]Event, error)

func (t Thread) ID() string
func (t Thread) SendInput(ctx context.Context, in RunInput) (string, error)
func (t Thread) Subscribe(ctx context.Context, fromSeq int64) (<-chan []Event, func())
```

3. Bind these rules:
   - No `sessions.db` / ADK / runner / policy / settle in `kit`. The contract carries events only; persistence and execution live in the implementation (apliq side).
   - `Subscribe` binds to the caller's `ctx` (request-scoped, never `context.Background`); the channel is always closed on termination; the caller owns cancel.
   - `Resume` recovers interrupted threads after restart (crash/deploy); it returns the threads needing continuation, nothing else.
   - Reuses the existing frozen `Event` / `RunInput` unchanged — no new envelope, no parallel types. Existing declarations (verbatim first lines from `agui/event.go`, `agui/input.go`):

```go
type Event struct {
```

```go
type RunInput struct {
```

## Context

`kit/agui` today freezes the protocol core (envelope + `Log` + `Emitter` + `Encode`/`Decode`/`Fold`) and `kit/hxchat` freezes the widget loop behind `Store`/`Runner` seams. What is missing is the app-facing session handle: a stable conversation (`threadId`) an app can create, reopen, subscribe to, and resume after restart — without importing apliq's `sessions.db`, ADK bridge, or settle policy.

Why it belongs in `kit` without backends: a fresh app should compile against `kit` alone (`NewRuntime` + `Thread` methods + `Event`/`RunInput`), wire its own `Store`/`Runner` (or the apliq implementation later), and get the lifecycle rules (cancel-scoped subscribe, close-on-terminate, resume-after-restart) as a compile-time contract. The backend (persistence, ADK execution, interrupts, settle) stays in apliq, behind this surface.

## Approaches

### A. Contract-only Runtime/Thread in kit, implementation in apliq (recommended)

`kit/agui` holds the `Runtime`/`Thread` shapes + doc comments only; a stub in-test implementation proves the shape; apliq provides the real backend later.

Tradeoffs: + app compiles against kit alone; + backend freedom (bbolt today, other stores tomorrow) without breaking the contract; + tiny review surface, testable close-on-cancel semantics now; − two-step delivery (contract then backend); − `OpenThread` without `ctx` cannot do I/O (deliberate: handle resolution only, I/O happens on `SendInput`/`Subscribe`).

### B. Full runtime with store/runner/policy in kit

`kit` ships a working runtime: persistence, ADK execution, interrupt/settle policy.

Tradeoffs: + one import runs everything; − drags `sessions.db`/ADK/policy/settle into kit, breaking the stdlib-only freeze and making kit an app server; − kit would dictate storage and model policy to every consumer. Rejected: violates the layering the protocol-core ADR froze.

### C. No runtime in kit — each app hand-rolls threads

Status quo: apliq keeps its own thread/session handling; future apps copy the pattern.

Tradeoffs: + zero kit change; − every app re-derives cancel/close/resume semantics, the exact sprawl `hxchat` was built to kill; − no shared compile-time contract for apliq to implement against. Rejected: pushes lifecycle correctness onto each consumer.

## Alternatives

- `OpenThread(ctx, threadID)` with context: considered, rejected for this cut — handle resolution is pure (no I/O), so no `ctx` per the brief's exact surface; I/O-bearing methods (`CreateThread`, `Resume`, `SendInput`, `Subscribe`, `ListActiveRuns`) all carry `ctx`.
- `Subscribe` returning `(<-chan Event, error)` single-event stream: rejected — batched `[]Event` matches `Log` replay/`Replay` framing and lets the implementation coalesce ticks without changing the shape.
- Generic `owner any` on `ListActiveRuns`: rejected — `owner string` keeps the contract stdlib-simple; implementations map their principal to a string.
- Including settle/interrupt policy in the contract: rejected — policy is backend behavior, not a shape; `RunInput.ValidateResume` already freezes the coverage rule.

## Consequences

Positive:

- Apps depend on `kit` only for the full thread lifecycle; apliq implements the surface without changing app code.
- Lifecycle bugs become contract violations: `Subscribe` close-on-cancel/terminate is testable once (stub proves it), inherited by every backend.
- `Resume` gives crash/deploy recovery a named home instead of ad-hoc replay scripts.

Tradeoffs / risks:

- Contract without backend looks dead until apliq implements it — Phase 2 tests carry the proof (stub exercising every method).
- `OpenThread` returning `(Thread, error)` on a missing thread vs empty handle needs implementation discipline (documented in `runtime.go`, enforced in backend review).
- `ListActiveRuns` `owner` semantics (who owns a run across restarts) are implementation-defined; the contract only fixes the parameter, not the partitioning.

## Implementation

Phase-gated per brief: Phase 1 = this ADR (proposed, review, accept); Phase 2 (after approval) = new file `agui/runtime.go` (shapes + doc comments, contract only) plus contract-shape tests (in-test stub, every method exercised, `Subscribe` close-on-cancel, no backend in kit). ADR + code stay name/shape-identical.

## Open items

- `OpenThread` missing-thread error shape (typed error vs `fmt.Errorf`) — settle in backend review.
- `ListActiveRuns` owner partitioning across restarts (per-user vs per-revision) — implementation decision in apliq.
- Whether `Resume` should also surface terminal outcome for already-finished threads — deferred to backend ADR.

## Addendum 2026-11-25 — standard ADK adapter (agui/adk.go)

Why kit vendors ADK here despite the stdlib-only freeze: the human chose the
kit-side home (option A) for the single shared ADK→AGUI translation, so agent
implementations consume it behind Runtime/Thread instead of each hand-rolling
the part→event mapping. Scope is translation only — `session`/`genai` types
in, agui `Event`s out — no runner, store, or policy, so the freeze holds
 everywhere else. Ported from `apliq/internal/agentv3/projection`
(`ProjectEvent`/`Fold` semantics preserved); kit-only deltas are `Part.Thought`
→ reasoning blocks, `RequestedInput` → activity messages, and `ErrorCode`/
`ErrorMessage` → `ADKRunError`. Requires `google.golang.org/adk/v2` +
`google.golang.org/genai` (same versions as apliq); the MVS bumps to
`golang.org/x/*` and `x/tools` come from that requirement, nothing else.
